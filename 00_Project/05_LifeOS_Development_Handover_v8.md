## 2. 財務模組技術架構（本次新增/變更部分）

### 2.1 負債帳戶餘額方向：真正的修正（Log #013 第一節，取代 Log #012 決策五十二的說法）

**重要更正**：Log #012 決策五十二描述的 `computeFinanceBalanceDelta` 函式從未真正存在於程式碼裡。實際在跑的 `applyTransactionBalanceChange`，資產與負債帳戶過去共用同一套方向，本輪才真正加上依 `account.category` 判斷方向反轉的邏輯：

- 資產帳戶：支出減少、收入/轉入增加（原本邏輯）
- 負債帳戶：**支出/轉出增加欠款、收入/轉入減少欠款**（方向相反）

新增交易與刪除交易的還原邏輯共用同一套判斷函式，交易編輯功能（見 2.4）也是呼叫同一套邏輯（先退回舊金額影響，再套用新金額影響）。**淨資產計算公式（`總資產 - 總負債`）假設負債帳戶 `balance` 存的是正數（欠多少）**，任何未來要動到餘額計算或初始餘額輸入的地方，都要確認遵守這個正數慣例。

### 2.2 分類標籤：全面改成自製下拉選單（Log #013 第二、三節）

記帳表單、記帳明細的標籤篩選，兩處原本都是原生 `<input list>`/`<select>`，在手機上有各自的呈現問題（datalist 擠成橫向捲動列、select 彈出系統原生清單無法客製化）。兩處都換成自製下拉選單元件：

- 記帳表單：`buildFinanceTagPicker(initialValue)`，可重複建立（不依賴固定 DOM id），供主表單跟交易編輯表單共用
- 明細篩選：獨立的按鈕+下拉，選中項目會反白標示
- 標籤旁邊有 ✏️ 重新命名功能：批次更新所有用過該標籤的歷史交易的 `tag` 欄位，不用另建標籤資料庫

### 2.3 記帳明細：篩選與呈現補強（Log #013 第三節）

- 新增**帳戶篩選**：月份／帳戶／標籤三者可疊加，轉帳交易只要來源或目標其中一邊符合就會被篩出
- 新增**加總小記**：篩選結果的支出/收入/轉帳合計（轉帳不算花費/收入，分開列）。**明確不是 Phase 3**，純粹加總畫面上已篩選出的數字，不涉及新資料結構
- **月份預設當月**：每次開啟明細都重置為當月，不記住上次選擇，其他月份/全部仍可手動切換

### 2.4 交易編輯（Log #013 第四節）

每筆交易可就地編輯**金額／日期／用途備註／分類標籤**。**刻意鎖定類型與帳戶不可編輯**（換類型/帳戶會讓餘額連動方向整個改變，風險遠高於修正金額）。核心送出邏輯抽成共用函式 `submitFinanceTransaction()`，表單、編輯、快捷按鈕都呼叫同一套，避免邏輯分裂。

### 2.5 快捷紀錄（Log #013 第五節，新增資料表）

```sql
create table finance_tx_presets (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users not null,
  label text not null,
  type text not null check (type in ('income', 'expense', 'transfer')),
  account_id uuid references finance_accounts(id),
  from_account_id uuid references finance_accounts(id),
  to_account_id uuid references finance_accounts(id),
  amount numeric not null check (amount > 0),
  category text,
  tag text,
  sort_order integer default 0,
  created_at timestamptz default now()
);
```

RLS 限本人讀寫。跟 `finance_transactions` 完全獨立，刪除/修改快捷範本不影響任何歷史交易。記帳彈窗新增快捷按鈕列，點按鈕＝直接用今天日期送出；旁邊 ✏️ 開啟獨立的「快捷設定」彈窗編輯範本本身。
